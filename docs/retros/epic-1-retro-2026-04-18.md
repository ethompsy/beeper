## Successes

1. **Pipeline proven end-to-end:** 116M metrics ingested, 424 anomalies detected, 15 investigations created autonomously
2. **Test-first approach:** Story 1.1's diagnostic baseline set the quality bar — every subsequent story grew the test count incrementally with zero regressions
3. **AD-1 protobuf verification required zero changes** — existing inline prost definitions matched OTEL Collector output perfectly
4. **AD-2 additive API pattern** worked cleanly across multiple extensions (Stories 1.2 and 1.4)
5. **Adversarial code reviews caught real bugs in every story:**
   - 1.1: Failure classifications corrected (6 errors misclassified)
   - 1.2: 4 MEDIUM issues (record_request position, field naming, bytes tracking)
   - 1.3: Empty-string guard missing in extract_service()
   - 1.4: M1 — warmup computation permanently stuck at 0 for metric-only workloads
6. **Test baseline revealed codebase 3.5x healthier** than architecture estimates (3,589 vs ~1,032 tests)

## Challenges

1. **Kind cluster OOMKill** — pre-existing 16h+ issue blocked Story 1.4 E2E verification. Tried 1Gi/2Gi/4Gi/unlimited memory — cluster was resource-starved. Resolved post-epic by eric allocating 32GB to Docker Desktop.
2. **E2E verification was consistently the slowest, most unpredictable task** in every story — Helm ConfigMap conflicts (1.2), OOMKill (1.4), pod restart issues
3. **Log pattern detection (AC3, Story 1.3) only PARTIAL** — OTel demo emits trace spans, not error-level log records. MetricDetector caught anomalies via metrics. LogDetector is wired and unit-tested but never fired in E2E.
4. **No one can confidently say "Beeper works as intended"** — only the first two links in the chain (ingestion → detection) are proven. Investigation execution, LLM analysis, and UI display are untested.

## Key Insights

1. **Demo environment reliability IS product quality** — if we can't run the demo, open source users can't either. This is a critical signal for adoption.
2. **Test-first with diagnostic baseline** should be repeated for every epic — Story 1.1's approach gave us confidence and direction.
3. **Unit tests prove code correctness but not system behavior** — E2E verification is mandatory, not optional.
4. **Adversarial code reviews earn their keep** — every review found real bugs that would have shipped otherwise.
