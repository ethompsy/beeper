## What Went Well

### 1. Template-Only Enhancement Pattern Accelerated Mid-Epic Delivery

Story 4-3 (Recommendations & Confidence Display) established a breakthrough insight: when the data pipeline is already complete, new UI features can be delivered as template-only enhancements — no new endpoints, services, or SSE events. This required zero backend changes while delivering rich interactive recommendation cards with confidence badges, risk indicators, and diagnostic action checklists. The pattern was partially reused in 4-4 (related KB entries reused existing KB data flow) and informed the approach in 4-5 and 4-6.

### 2. SSE Polling-Backed Architecture Proved Extensible

The SSE streaming pattern established in 4-1 (`investigation_stream()`) scaled cleanly across the epic. Each story added new SSE event types by following the same pattern:
- 4-1: `investigation-update` (list changes)
- 4-2: `step-update`, `findings-update`, `investigation-complete`
- 4-4: `kb-update` (KB query step completion)
- 4-5: `confirmation-update` (confirmation state changes)
- 4-6: `resolution-update` (resolution outcome changes)

The generator-based polling architecture and `stream_with_context` pattern from Flask worked reliably. Change-detection logic (compare current vs. previous poll) prevented unnecessary SSE events.

### 3. Adversarial Code Reviews Caught Real Security and UX Issues

Every story underwent adversarial code review, producing 40 total issues (7 HIGH, 21 MEDIUM, 12 LOW). HIGH severity findings included:
- SSE sending JSON instead of HTML partials, breaking HTMX swap compatibility (4-1)
- HTMX `hx-target="body"` breaking SPA-like navigation — SSE never connected on detail pages (4-2)
- Duplicate alternative hypotheses section creating user confusion (4-3)
- Missing SSE `kb-update` test — event was untested (4-4)
- Duplicate `resolution_notes` textarea names causing stale form data submission (4-6)

These were functional bugs that would have degraded UX or caused data issues in production.

### 4. HTMX Partial Rendering Pattern Eliminated JavaScript Complexity

The entire Epic 4 UI was built with zero custom JavaScript (beyond the HTMX SSE extension). All dynamic behavior — filtering, navigation, real-time updates, form submissions, confirmation flows — was handled through HTMX attributes (`hx-get`, `hx-post`, `hx-target`, `hx-swap`, `sse-connect`, `sse-swap`). This kept the codebase simple, debuggable, and consistent.

### 5. Consistent Service Layer Pattern Prevented Resource Leaks

Every service used the same lazy-initialized `httpx.Client` with connection pooling and a `close()` method. Code reviews in 4-2, 4-4, and 4-5 caught resource leak patterns (SSE generators not closing services on early exit, Qdrant clients not closed), and fixes were applied consistently. By 4-6, the pattern was internalized and no resource leaks were found.

## What Could Be Improved

### 1. SSE Event Independence Was a Recurring Review Finding

Stories 4-5 and 4-6 both had SSE change-detection logic that was coupled to other data changes. In 4-5, the `confirmation-update` event was nested inside the `findings` key-change block, so confirmations that changed without findings changing were missed. In 4-6, the `resolution-update` event had the same coupling issue. Both were caught in review and fixed.

**Action:** When adding new SSE event types, always implement independent change detection per event. Each tracked field should have its own previous-value variable in the generator loop.

### 2. Resource Cleanup in SSE Generators Required Multiple Fixes

Stories 4-2, 4-4, and 4-5 all had resource leak issues in SSE generators — services or clients not being closed in `finally` blocks, or not closed on early-exit paths (e.g., 404 responses). This pattern was caught in review each time.

**Action:** Establish a standard SSE generator template with `try/finally` cleanup for all services and clients, including early exit paths. Apply to new SSE endpoints going forward.

### 3. WCAG Accessibility Was Addressed Reactively, Not Proactively

Accessibility improvements — ARIA `role="alert"` on warning banners (4-3), `role="status"` on confirmation banners (4-5), contrast ratio fixes for yellow badges (4-3) — were all caught in code review rather than built into the initial implementation.

**Action:** Include WCAG compliance in the template development checklist. Check contrast ratios for color-coded badges and add ARIA roles to dynamic status elements during initial implementation.

### 4. URL Construction Inconsistency Between Templates

Story 4-4 review found hardcoded `/knowledge/` URLs in `_findings.html` while `_related_kb.html` used `url_for()`. This inconsistency in URL generation across templates could cause issues if route prefixes change.

**Action:** Always use `url_for()` for URL generation in Jinja2 templates. Avoid hardcoded route paths.

## Lessons Learned for Epic 5

### Technical Patterns to Follow

- Use polling-backed SSE generators with `stream_with_context` for real-time updates
- Each SSE event type needs independent change detection — never nest event checks inside other event blocks
- Template-only enhancements for new UI features when data pipeline exists — avoid unnecessary backend changes
- `close()` method on every service class — call in SSE generator `finally` blocks and route `finally` blocks
- `url_for()` for all URL generation in Jinja2 templates — never hardcode route paths
- HTMX `hx-post` with `hx-target` for form submission without page reload
- Conditional form field visibility with `disabled` attribute on hidden inputs to prevent stale data
- Register Jinja2 template filters and globals in `app.py` for shared formatting utilities

### Testing Patterns

- Test SSE event independence — verify events fire on their specific data changes, not only when other data changes
- Test resource cleanup — verify `close()` is called in all code paths (success, error, early exit)
- Test WCAG compliance — verify ARIA roles on dynamic elements, contrast ratios on color-coded badges
- Test form validation — verify required fields, invalid enum values, conditional field requirements
- Mock Qdrant with `MagicMock` — never connect to real Qdrant in tests
- Mock operator with `respx` — never make real HTTP calls in tests
- Test both full page and HTMX partial responses for every route

### Process Patterns

- Adversarial code review on every story — caught 40 issues across the epic
- Template-only stories can be delivered faster but still need full code review for accessibility and data handling
- SSE event testing should be part of initial implementation, not deferred to review
- WCAG compliance should be part of template development checklist, not caught in review
- Resource cleanup patterns in SSE generators should be templated and consistent
