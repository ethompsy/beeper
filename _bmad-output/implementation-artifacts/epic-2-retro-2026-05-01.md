## Successes

1. **100% story completion** — all 10 stories (5 prep + 5 main) delivered
2. **Adversarial code reviews caught real bugs in every story (5/5):** N+1 queries (2.5), Qdrant ordering (2.5), missing env var fallback (2.2), vector dimension mismatch (2.3), schema gaps in early-return paths (2.4)
3. **Data propagation pattern established (2.4) and replicated cleanly (2.5):** StepResult.data → pipeline_metadata → extract helper → format for prompt — good architecture compounds
4. **Investigation lifecycle proven E2E:** Pending→Running→Completed in ~31s, deterministic Job naming, no duplicates on restart
5. **Prep task pattern from Epic 1 retro paid off:** Walking into Epic 2 with cluster stability, test baselines, and verified Qdrant/LLM config prevented surprises
6. **Zero regressions across entire epic** — 572 Rust tests, 1015+ Python tests, all passing throughout

## Challenges

1. **SLO engine memory leak carried across entire epic unresolved** — operator restarted 596+ times, memory limits bumped 3 times (512Mi → 1Gi → 2Gi), root cause never diagnosed. Team euphemized it as "OOMKill" and "pre-existing blocker" instead of calling it what it is: a memory leak
2. **E2E verification achieved in only 1/5 main stories** — same memory leak blocked Stories 2.2–2.5. "E2E deferred" appeared in four consecutive stories without triggering a bug task
3. **Integration seam bugs in every story** — wrong field names (2.5: `status.burnRate` doesn't exist), missing env vars (2.2: `LOKI_URL`), vector dimension mismatch (2.3: 1536→1), data not flowing through pipeline (2.4, 2.5). Code within components was correct; wiring between components was consistently broken
4. **Communication gap** — blockers were documented in story Dev Notes but never surfaced in prompt output where eric could see them. Eric learned about the memory leak for the first time in this retrospective

## Key Insights

1. **Call bugs what they are and fix them immediately** — "memory leak" not "OOMKill." Clear language drives action. Deferral compounds cost.
2. **Communicate in the prompt, document in the file** — eric reads the conversation, not the markdown. If it's not raised in prompt output with clear severity, it doesn't exist for the project lead.
3. **Integration seams are where bugs hide** — every story found mismatches at component boundaries. This is where testing and verification effort should focus.
4. **Good patterns compound** — the data propagation pattern from Story 2.4 replicated cleanly in 2.5. Investing in clean architecture pays dividends immediately.
5. **Fix blockers when found, don't defer** — the same memory leak appeared in four stories. Fixing it in Story 2.2 would have unblocked E2E for three subsequent stories.
