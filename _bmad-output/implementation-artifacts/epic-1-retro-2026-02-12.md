## What Went Well

### 1. Pattern Reuse Accelerated Development
Story 1-5 (Loki Adapter) explicitly built on patterns established in 1-4 (Prometheus Adapter). The adapter pattern, error handling, and testing approach carried forward. Dev Notes sections referencing previous stories enabled continuous improvement.

### 2. Adversarial Code Reviews Caught Real Issues
Every story had 5-8 issues identified by review. HIGH severity issues included:
- Missing `INVESTIGATION_NAMESPACE` env var (1-9)
- Insecure `SECRET_KEY` handling (1-7)
- Timestamp calculation bugs (1-4)
- Missing datetime indexes (1-2)

### 3. Comprehensive Test Coverage
Grew from 0 to 183 tests. Testing strategy of unit tests + integration tests with mocks (wiremock for Rust, respx for Python) provided confidence without requiring live infrastructure.

### 4. Story-Level Documentation
Each story's Dev Notes included patterns from previous stories. Code Review Records documented issues found and fixes applied. This creates institutional knowledge.

## What Could Be Improved

### 1. Timestamp Handling
Stories 1-2 and 1-4 both had hand-rolled date calculations that were buggy. We learned to use `chrono` in Rust but it took two stories to internalize.

**Action:** Add "use chrono for timestamps" to architecture patterns.

### 2. Task Description Accuracy
Stories 1-5 and 1-6 had tasks marked complete that didn't match actual implementation. Code review caught these discrepancies.

**Action:** Update task descriptions when implementation diverges from plan.

### 3. Documentation as Part of Done
Story 1-8 received HIGH severity finding for "README not updated." Documentation should be verified during story completion, not caught in review.

**Action:** Add "Documentation updated" checkbox to story completion criteria.

### 4. Connection Pooling Pattern
Story 1-7 revealed we were creating new HTTP clients on every request. This pattern should be established from the first service implementation.

**Action:** Document lazy client initialization pattern in architecture.

## Lessons Learned for Epic 2

### Technical Patterns to Follow
- Use `chrono` for timestamps in Rust, never hand-roll
- Use `#[serde(rename_all = "snake_case")]` on all Rust structs
- Create reusable error helpers to reduce duplication
- Initialize HTTP clients once, reuse with connection pooling
- Add ARIA attributes for accessibility from the start
- Use `secrets.token_hex(32)` for Flask SECRET_KEY in dev

### Testing Patterns
- Use wiremock for Rust HTTP mocking
- Use respx for Python httpx mocking
- Verify auth headers are sent in integration tests (use header matchers)
- Mock external services in UI tests

### Process Patterns
- Update task descriptions when implementation diverges
- Include README updates in story scope
- Keep File List in Dev Agent Record accurate
- Mark deferred tasks as "DEFERRED" with explanation
