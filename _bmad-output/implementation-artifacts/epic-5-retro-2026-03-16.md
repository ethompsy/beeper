## What Went Well

### 1. Two-Channel Architecture — SocketIO + SSE Coexistence Validated

The single most impactful architectural decision of Epic 5: establishing a two-channel real-time pattern where Flask-SocketIO handles collaboration (messages, annotations, redirects, approvals, KB feedback) while SSE handles investigation progress updates. Both channels coexist on the same page without interference. This pattern was established in Story 5-1 and reused seamlessly across all subsequent stories. The clean separation means collaboration features never block or interfere with investigation progress streaming.

### 2. Zero CRITICAL Issues — Third Consecutive Epic

Continuing the trend from Epics 3 and 4, all 35 code review findings across 6 stories were MEDIUM (22) or LOW (12) severity, with only 1 HIGH. The diminishing severity curve across v0.2.0 (Epic 1: occasional CRITICAL → Epic 2: 7 CRITICAL → Epic 3: 0 CRITICAL → Epic 4: 0 CRITICAL → Epic 5: 0 CRITICAL) confirms that accumulated patterns, conventions, and adversarial reviews are systematically preventing serious bugs.

### 3. Service Composition Pattern — Clean, Consistent Architecture

Every new service in Epic 5 follows the same pattern: compose existing services, provide graceful degradation, and expose both route and WebSocket interfaces. This emerged organically:

| Service | Composes | Graceful Degradation |
|---------|----------|---------------------|
| HandoffService | InvestigationService + SloService | One service fails → partial handoff with empty section |
| KBSurfacingService | KBService + EmbeddingService | Semantic search fails → fallback to service-based listing |
| EvidenceService | Pipeline metadata extraction | Missing fields → skip evidence type, continue rendering |
| CollaborationService | Qdrant collaboration_messages | Persistence fails → message still delivered via WebSocket |

This pattern should be documented as a standard for Epic 6.

### 4. Graceful Degradation — Consistent Error Resilience

Every new feature degrades gracefully when dependencies are unavailable. HandoffService returns partial summaries when InvestigationService or SloService fails. KBSurfacingService falls back from semantic search to service-based listing when EmbeddingService is unavailable. WebSocket handlers continue broadcasting even when operator API calls fail. This "never crash the whole feature" philosophy was applied consistently and caught in code reviews when missing.

### 5. Keyboard-First UX — All Primary Actions Via Shortcuts

All collaboration features are keyboard-accessible: `n` for annotate, `r` for redirect, `a` for instant approve, `x` for reject, `Enter` to submit, `Escape` to cancel. No modal dialogs — all inline inputs. This keyboard-first approach means SREs can interact with Beeper during incidents without leaving their terminal-adjacent workflow.

UI test count grew from 1,388 to 1,625 (+237, 17% growth) with zero regressions. Each story added 25-63 tests, and code reviews consistently added 1-3 tests per story. The mid-epic QA checkpoint found zero regressions — the cleanest checkpoint in v0.2.0.

## Challenges & Growth Areas

### 1. Flask-SocketIO Handler Registration Timing — Story 5-1 Gotcha

Flask-SocketIO requires event handlers to be imported BEFORE `init_app()` is called, but the module-level app initialization conflicts with the SocketIO test client. This was resolved with a guarded `if __name__` pattern, but it caused initial confusion. The leave_room() / broadcast ordering (broadcast before leave_room, not after) was another timing subtlety that required debugging.

**Lesson:** Document real-time framework initialization requirements in the architecture. Future stories involving SocketIO or SSE should reference this pattern.

### 2. SSE Test Assertion Churn — Evidence Timeline Event Count Drift

Story 5-2 introduced the `evidence-timeline-update` SSE event, which broke 4 existing SSE integration tests that asserted specific event counts. This mirrors the pipeline step count assertion churn from Epic 4 but in the SSE domain.

**Root Cause:** Hard-coded SSE event count assertions in integration tests. Each new SSE event type cascades across prior test files.

**Lesson:** Same as Epic 4's pipeline step count issue — consider centralizing expected event counts or using more flexible assertions.

### 3. Operator API Endpoints Not Yet Implemented — Graceful Degradation Masked Integration Gaps

Stories 5-3 and 5-4 forwarded annotations, redirects, approvals, and rejections to operator API endpoints (`/annotate`, `/redirect`, `/approve`, `/reject`) that don't yet exist in the Rust operator. The graceful error handling pattern meant this wasn't blocking, but it also means the full integration path has never been tested end-to-end.

**Impact:** Low for Epic 5 (collaboration features work via WebSocket even without operator integration). Medium risk for future epics if operator endpoints aren't implemented before production.

**Lesson:** Track mock-backed integrations separately from fully-integrated features. Epic 6 should verify whether operator endpoints are needed.

### 4. CSS Namespace Proliferation — Three Naming Conventions

Epic 5 introduced three new CSS namespace prefixes: `.collab-*` (collaboration panel), `.handoff-*` (shift handoffs), `.kb-surfacing-*` (KB surfacing). Combined with existing prefixes from earlier epics, the CSS is growing without a formal naming convention document.

**Impact:** Low — namespaces prevent conflicts. But discoverability and consistency suffer without documentation.

**Lesson:** Document CSS namespace conventions before Epic 6 adds more.

### 5. SBAR Badge Color Palette Reuse — Minor UX Concern

The SBAR letter badges (S=blue, B=gray, A=amber, R=green) reuse colors from evidence timeline type badges. In the current UI, these never appear on the same page, so there's no actual confusion. But as the UI grows, a formalized color palette would prevent accidental semantic overlap.

## Key Insights

1. **Two-channel real-time architecture scales cleanly.** SocketIO and SSE serve fundamentally different purposes (bidirectional collaboration vs. unidirectional progress streaming). Keeping them separate prevents complexity in both channels and allows each to evolve independently. This should be a documented architectural principle.

2. **Service composition with graceful degradation is the right pattern for UI services.** Every Epic 5 service composes 2+ upstream services and handles failures gracefully. This pattern prevented cascading failures and kept the UI responsive even when backend services were unavailable. Formalize this as a standard.

3. **Optimistic UI builds trust in real-time interfaces.** The fix approval button's immediate feedback (spinner → "Executing...") was a small UX detail with outsized impact. Users feel in control when the UI responds instantly. Consider applying optimistic UI to more interactions in Epic 6.

4. **Keyboard shortcuts transform SRE workflow efficiency.** The `a` for instant approve (single keystroke, no confirmation dialog) was specifically designed for incident response speed. SREs under pressure shouldn't need multiple clicks. This keyboard-first philosophy should continue.

5. **Novel issue detection creates a compounding intelligence advantage.** Story 5-6's detection of novel issues (empty KB search → `novel_issue_candidate: true`) feeds directly into Epic 6's automatic KB entry creation (Story 6-1). Each investigation either retrieves existing knowledge or flags a knowledge gap — the system gets smarter either way.

6. **Composite ranking (relevance * validation weight) is more useful than raw similarity.** Story 5-6's ranking formula ensures a proven fix with 0.6 relevance outranks an AI-generated entry with 0.7 relevance. This matches SRE mental models — a proven solution is always more valuable than an unverified one.

7. **SBAR structure for handoffs is a competitive differentiator.** The medical SBAR protocol (Situation/Background/Assessment/Recommendation) gives structure to what is typically a chaotic verbal handoff. The 30-second scan UX (all sections expanded by default, clickable links, copy to clipboard) transforms shift transitions.
